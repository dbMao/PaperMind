## F-01：大模型配置

### 描述
用户在前端设置页填写 API 信息，后端动态创建 LangChain LLM 实例。

### 配置项

| 字段 | 说明 | 示例 |
|---|---|---|
| API 地址 (Base URL) | 兼容 OpenAI 格式的 API 端点 | `https://api.openai.com/v1` |
| API 密钥 (API Key) | 鉴权密钥 | `sk-xxx` |
| 模型名称 (Model) | 模型 ID | `gpt-4o`、`deepseek-chat` |
| 高级参数 | temperature、max_tokens（可选，有默认值） | |

### 规则
- 配置保存在后端本地（SQLite），前端通过 API 读写
- 切换模型后，下一次对话即生效
- embedding 模型（all-MiniLM-L6-v2）始终本地运行，启动时自动检测部署状态
- 若未部署，设置页提示一键部署（~90MB 下载）
- 勾选 “AI 增强 PDF 解析” 时，警告用户将消耗更多 tokens

## F-02：论文库管理

### 描述
论文库位于左侧，支持上传、列表、删除。

### 功能点

| 功能 | 说明 |
|---|---|
| 本地上传 | 支持 PDF 文件上传，拖拽或文件选择器 |
| 论文列表 | 显示已上传论文的标题、作者、上传时间 |
| 搜索/筛选 | 按标题关键词搜索；按标签筛选 |
| 删除 | 删除论文及其向量索引 |
| 文件夹管理 | 支持创建、重命名、删除文件夹；论文可移入文件夹 |
| 元数据展示 | 论文标题、作者、年份、摘要（自动提取或手动编辑） |

### 上传流程
1. 用户选择 PDF 文件（可指定目标文件夹）
2. 前端显示上传进度
3. 后端：
   a. 保存原始 PDF
   b. PyMuPDF 提取纯文本 + 标题层级 → 存入 SQLite
   c. 若检测到表格 → pdfplumber 补充提取
   d. 若用户勾选 AI 增强 → unstructured.io 语义分割
   e. 文档切分（按节切分策略，见 F-03）→ embedding → 写入 ChromaDB
4. 前端列表更新

## F-03：PDF 解析与文档切分

### 三级解析策略

| 层级 | 引擎 | 触发条件 | 用途 |
|---|---|---|---|
| 主力 | PyMuPDF | 始终执行 | 提取纯文本、图片、标题层级 |
| 补充 | pdfplumber | PyMuPDF 检测到表格区域时自动触发 | 表格结构化提取 |
| AI 增强 | unstructured.io | 用户在上传时勾选（可选） | 高精度语义分块，按章节标题切分 |

### AI 增强提示
- 上传对话框中提供复选框：“启用 AI 增强语义解析”
- 勾选后提示：“此选项将调用您配置的大模型 API 进行语义分割，会消耗额外 tokens。建议仅对重要论文使用。”

### 文档切分策略（Chunking）

利用论文自身的标题/段落边界进行语义切分，而非固定 token 数硬切。

#### 切分步骤

```
1. PyMuPDF 提取文本 + 字号/字体信息 → 识别标题层级（##、### 等）
2. 按“节”（Section）为单位切分：
   - 每个 ## 或 ### 标题及其下属内容作为一个 chunk
   - 每个 chunk 记录元数据：{ paper_id, section_title, heading_level, page_number }
3. 超长节处理：
   - 若某节超过 1500 tokens → 按段落边界二次切分
   - 子 chunk 之间保留 200 token 的 overlap
4. 短节合并：
   - 若相邻小节均 < 200 tokens → 合并为一个 chunk（如“致谢”+“参考文献”）
5. 每个 chunk 的 ChromaDB metadata：
   {
     "paper_id": 1,
     "title": "Attention Is All You Need",
     "section": "3. Model Architecture",
     "heading_level": 2,
     "page": 3,
     "chunk_index": 5
   }
```

#### 参数默认值

| 参数 | 默认值 | 说明 |
|---|---|---|
| `chunk_max_tokens` | 1500 | 单 chunk 上限（触发二次切分） |
| `chunk_min_tokens` | 200 | 短节合并阈值 |
| `overlap_tokens` | 200 | 超长节切分时的重叠量 |
| `encoding` | cl100k_base | tiktoken 编码器（计 token 数用） |

## F-04：智能对话（RAG QA）

### 描述
基于论文内容的多轮对话问答，回答附带引用来源。

### 交互方式
1. **自由提问**：在输入框直接输入问题，在选中论文范围内检索回答
2. **划词提问**：在论文内容区域选中一段文字 → 右键/悬浮按钮 “基于此提问” → 选中的文本自动填入对话上下文

### 核心流程
```
用户提问
  → embedding → ChromaDB 相似度检索（top-k chunks）
  → LangChain Prompt 模板（system: 你是论文阅读助手，基于提供的论文内容回答问题）
  → LLM 生成回答
  → 返回回答 + 引用片段 + 来源论文标题
```

### 对话模式
- **单篇模式**：选中某篇论文后，检索范围限定为该论文
- **全局模式**：未选中论文时，检索范围为整个论文库

## F-05：论文翻译

### 描述
使用本地部署的 Helsinki-NLP/opus-mt-en-zh 模型，对论文正文进行英译中，以左右对照方式展示。

### 模型信息

| 项目 | 说明 |
|---|---|
| 模型名称 | Helsinki-NLP/opus-mt-en-zh |
| 架构 | MarianMT（Transformer 编码器-解码器） |
| 大小 | ~300 MB |
| 运行方式 | 本地 CPU/GPU，数据不出本机 |
| 翻译方向 | 英文 → 中文 |

### 部署流程
1. 用户在论文详情页点击 “显示翻译”
2. 后端检查模型是否已部署 → 未部署则前端弹出确认对话框
3. 用户点击 “同意并部署” → 后端执行 `scripts/deploy_opus_mt.py` 下载模型
4. 部署完成 → 自动开始翻译

### 翻译展示
- 左右分栏对照：左侧原文（EN），右侧译文（ZH）
- 按段落逐段对齐
- 翻译结果缓存（同论文再次打开无需重新翻译）
- 点击 “隐藏翻译” 恢复普通视图

### 交互
- 按钮文字：🌐 显示翻译 / 🌐 隐藏翻译
- 翻译中显示进度条

## F-06：论文对比

### 描述
选择多篇论文（2-5 篇），对比分析异同。

### 对比维度
- 研究问题
- 方法论
- 数据集
- 实验结果
- 优劣势分析

### 交互
- 论文列表中多选 → 点击 “对比分析”
- 结果以表格 + 文字分析展示

### 检索策略：两轮检索

```
第一轮 — 全局检索：
  用户对比问题 → embedding → ChromaDB 全局检索 top-m（m=10）
  → 快速定位最相关的论文和片段

第二轮 — 针对性补充：
  对第一轮命中的每篇论文，单独检索 top-n（n=5）
  → 确保每篇论文都有充分的信息覆盖

合并去重：
  → 两轮结果合并，按相关性排序，去重（同 chunk 去重）
  → 构建 prompt 送给 LLM 生成对比分析
```

### 参数默认值

| 参数 | 默认值 | 说明 |
|---|---|---|
| `compare_top_m` | 10 | 第一轮全局检索数量 |
| `compare_top_n` | 5 | 第二轮单篇补充检索数量 |

## F-07：对话历史

### 描述
每次对话保存为会话（Session），支持查看历史、继续对话。

### 规则
- 会话按论文关联（单篇对话）或独立（全局对话）
- 历史列表按时间排序
- 对话记录保存到 SQLite

## F-08：文件夹管理

### 描述
支持创建文件夹来组织论文库。

### 功能点

| 功能 | 说明 |
|---|---|
| 创建文件夹 | 在论文库左侧创建新文件夹 |
| 重命名文件夹 | 右键或双击文件夹名修改 |
| 删除文件夹 | 删除空文件夹（含论文时提示确认） |
| 移动论文 | 拖拽论文到目标文件夹 / 右键菜单移动 |
| 文件夹列表 | 文件夹树结构展示，支持折叠/展开 |
| “全部论文”视图 | 默认视图，显示所有论文忽略文件夹 |

### 规则
- 文件夹仅用于前端组织展示，不影响向量检索范围
- 检索时仍通过 `paper_id` filter 限定范围
- 文件夹信息存储在 SQLite 中

## F-09：推理强度与预设功能

### 描述
在对话框输入区域上方提供推理强度选择器和预设功能下拉菜单，用户可在发送消息前选择推理强度（如果模型支持）和预设的 Prompt 模板，影响发送给 LLM 的 system prompt。

### 推理强度

| 级别 | 值 | 说明 |
|---|---|---|
| 低 | `low` | 快速响应，适合简单问答 |
| 中 | `medium` | 均衡推理（默认） |
| 高 | `high` | 深度思考，适合复杂分析 |

### 预设功能列表

| 预设 | ID | 用途 | 适用模式 |
|---|---|---|---|
| 摘要 | `summarize` | 生成结构化论文摘要：背景→方法→发现→结论→局限 | 单篇 |
| 对比 | `compare` | 多维度对比分析：研究问题/方法/数据/结果/创新点/局限 | 多篇 |
| 算法分析 | `algorithm` | 深度技术分析：输入输出/复杂度/trade-off/baseline/改进空间 | 单篇/多篇 |
| 参考文献整理 | `references` | 引文结构化整理：关键引用/关系分类/缺失推荐/引用网络 | 单篇 |

### Prompt 模板位置

所有预设 Prompt 定义在 [frontend/src/api/prompts.js](../frontend/src/api/prompts.js)，支持占位符：
- `{context}` — RAG 检索到的论文上下文
- `{question}` — 用户输入的问题
- `{paper_title}` — 当前选中论文标题

### 交互
- 点击输入框上方的 “⚡ 预设功能” 按钮 → 展开下拉菜单
- 选择预设后按钮变为 “{图标} {预设名}”，输入框 placeholder 随之变化
- 再次点击同一预设可取消选择，恢复默认问答模式
- 推理强度默认 “中”，切换即时生效

### 后端影响
- `/api/chat/ask` 请求体新增字段：
  - `reasoning_effort`: `"low"` | `"medium"` | `"high"`
  - `preset_id`: `"summarize"` | `"compare"` | `"algorithm"` | `"references"` | `null`
- 后端根据 `preset_id` 选择对应的 system prompt 模板
- 后端根据 `reasoning_effort` 设置 LLM 的 `reasoning_effort` 或 `thinking` 参数（模型支持时）
